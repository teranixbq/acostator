# Acostator — Database Schema

## Entity Overview

```
User
 └─ has many Projects
      └─ has many Annotations (quadruples)
           ├─ AspectTerm (span or implicit)
           ├─ OpinionTerm (span or implicit)
           ├─ Category (references CategoryPool)
           └─ Sentiment

Project
 └─ has many Categories (CategoryPool)

Note: DatasetRows are NOT stored in D1. The CSV file stays in R2.
      Row text is loaded in the browser at annotation time.
```

## Entities

### Project
```

file_name         String   (original CSV filename)

// Computed

```

### DatasetRow

> **Not stored in D1.** The CSV file is stored permanently in R2. Row data (including text) is
> fetched directly from R2 and parsed in the browser at annotation time using the project's
> `text_column`. D1 does not hold a copy of any row content.

### Category
```
id           String   @id @default(cuid())

```

## CSV Import Format

The uploaded CSV file must have at least one text column. At upload time, the user selects which column to annotate via the Column Picker. The selected column name is saved as `text_column` on the Project.

| Column | Description |
|---|---|
| Any column selected by the user | Text content to be annotated |

The full CSV is stored as-is in R2. No row content is inserted into D1.

---

## Category Recommendation Logic

When an annotator selects a category for a new quadruple:

1. Fetch all `Category` records within the same project
2. Sort by `usage_count DESC` (most used → top of list)
3. Display as a suggestion list with fuzzy search
4. If no match found → allow creating a new category

---

## Progress Calculation

```
project.annotated_rows = COUNT(DISTINCT row_index FROM Annotation WHERE project_id = ?)
project.progress_pct   = (annotated_rows / total_rows) * 100
```

A row is considered annotated once it has at least one Annotation saved for it. There is no explicit row status in D1 — progress is derived from the Annotation table.

---

## Soft Delete Strategy

- Project: soft delete (add `deleted_at`)
- DatasetRow: not stored in D1; no delete strategy needed
- Annotation: hard delete is fine (can be undone via re-annotation)
- Category: soft delete if `usage_count = 0`, protected if currently in use
