# Acostator — Product Definition

## Overview

Acostator is a web-based annotation tool for manually annotating ABSA (Aspect-Based Sentiment Analysis) datasets using the **ACOS (Aspect-Category-Opinion-Sentiment) Quadruple Extraction** schema.

The tool is designed for NLP researchers and practitioners who need an efficient interface to create ground-truth ACOS datasets manually.

---

## Problem Statement

Creating ACOS datasets manually is tedious because each text can have multiple quadruples, and no tool exists that is purpose-built for this workflow. Spreadsheets are not enough — annotators need an interface that can highlight text spans, track progress, and export in a standard format.

---

## Target User

NLP researchers and students conducting ABSA research who need ground-truth ACOS datasets.

---

## Core Concepts

### ACOS Quadruple
Each text can have one or more quadruples:

| Element | Description | Type |
|---|---|---|
| **Aspect Term** | Word/phrase in the text that is the subject of sentiment | Text span or Implicit |
| **Category** | Aspect category (e.g., BATTERY, DISPLAY, SERVICE) | Predefined + extensible |
| **Opinion** | Word/phrase in the text that expresses the opinion | Text span or Implicit |
| **Sentiment** | Sentiment polarity | Positive / Negative / Neutral / Mixed |

### Implicit
When an Aspect or Opinion does not appear explicitly in the text, the annotator must still define all ACOS elements manually — it cannot be skipped.

### Text Column
When uploading a CSV, the user selects which column contains the text to annotate. This is stored as `text_column` on the project and used to parse CSV rows in the browser.

## User Flow

### 1. Auth
- Login via GitHub OAuth
- One account = one user, no additional roles/permissions for now

### 2. Project Management
- A user can have many projects
- One project = one CSV dataset (max 1GB)
- Project shows progress: how many rows have been annotated vs total
- Annotation order is configurable per project:
  - **Sequential** (default) — rows are presented in CSV order, starting from index 0
  - **Random** (optional) — rows are presented in a randomized order, useful to reduce positional bias in annotation

### 3. CSV Upload with Column Picker
```
User selects CSV file
  → Browser parses header row locally (no upload yet)
  → User picks which column contains annotation text (text_column)
  → Browser uploads file directly to R2 via presigned URL
  → Worker records text_column on project
  → CSV stays in R2 permanently
```

### 4. Annotation Flow (per row)
```
Open row
  └─ Highlight Aspect Term in text (click+drag)
      ├─ [or] Mark as Implicit → enter aspect text manually
      └─ After aspect is selected:
          └─ Highlight Opinion in text (click+drag)
              ├─ [or] Mark as Implicit → enter opinion text manually
              └─ After opinion is selected:
                  └─ Select Sentiment (Positive / Negative / Neutral / Mixed)
                      └─ Select or create Category
                          └─ Add Annotation → saved locally
```

Multiple quadruples can be added per row before completing.

### 5. Local-First Annotation Storage
- All annotation work is done in the browser
- CSV rows are cached in IndexedDB after first fetch
- Pending annotations stored in IndexedDB and in-memory
- Navigation (Previous/Next) is fully local — no API call
- On "Complete": annotations are synced to D1 via POST (upsert)

### 6. Progress Navigation
- **Next** — advance to next row (marks current as completed if annotations exist)
- **Previous** — go back to previous row (loads from IndexedDB cache)
- **Complete** — explicitly sync current row annotations to server
- Sync status indicator: idle / syncing / synced / error

### 7. Export
- JSON export: one entry per row, with array of quadruples
- CSV export: one row per quadruple, joined with original CSV text

## Export Format

### JSON
```json
[
  {
    "row_index": 0,
    "text": "The battery life is amazing but the screen is terrible.",
    "quadruples": [
      {
        "aspect_term": "battery life",
        "aspect_implicit": false,
        "aspect_start": 4,
        "aspect_end": 16,
        "category": "BATTERY",
        "opinion_term": "amazing",
        "opinion_implicit": false,
        "opinion_start": 20,
        "opinion_end": 27,
        "sentiment": "positive"
      },
      {
        "aspect_term": "screen",
        "aspect_implicit": false,
        "aspect_start": 35,
        "aspect_end": 41,
        "category": "DISPLAY",
        "opinion_term": "terrible",
        "opinion_implicit": false,
        "opinion_start": 45,
        "opinion_end": 53,
        "sentiment": "negative"
      }
    ]
  }
]
```

### CSV
```
id,text,aspect_term,aspect_implicit,aspect_start,aspect_end,category,opinion_term,opinion_implicit,opinion_start,opinion_end,sentiment
row_001,"The battery life is amazing...",battery life,false,4,15,BATTERY,amazing,false,19,26,positive
```

## Scope (v1)

### In Scope
- GitHub OAuth login
- Multi-project per user
- CSV dataset upload (max 1GB) with column picker
- Annotation interface with text highlighting and span selection
- Implicit aspect/opinion support
- Category management with history-based recommendations
- Progress tracking per project and per row
- Annotation order mode: sequential (default) or random (optional)
- Local-first annotation with IndexedDB cache
- Sync to D1 on Complete (upsert, idempotent)
- JSON and CSV export

### Out of Scope (v1)
- Multi-annotator / project sharing
- Inter-annotator agreement (IAA)
- Review / adjudication workflow
- Input formats other than CSV
- Model-assisted pre-annotation
- Real-time collaboration
