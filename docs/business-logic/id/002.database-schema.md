# Acostator — Data Model

## Entity Overview

```
User
 └─ has many Projects
      └─ has many Annotations (Quadruples)
           ├─ AspectTerm (span atau implicit)
           ├─ OpinionTerm (span atau implicit)
           ├─ Category (references CategoryPool)
           └─ Sentiment

Project
 └─ has many Categories (CategoryPool)
```

Catatan: `DatasetRow` tidak lagi ada sebagai tabel D1. Baris CSV disimpan di R2 (sebagai file asli) dan di-cache di IndexedDB browser. Hanya quadruple yang disimpan di D1.

---

## Entities

### User
```
id           String   @id (dari OAuth provider)
github_id    String   @unique
username     String
email        String?
avatar_url   String?
created_at   DateTime
updated_at   DateTime
```

### Project
```
id                String   @id @default(cuid())
user_id           String   (FK → User)
name              String
description       String?
file_name         String   (nama file CSV asli)
file_size         Int      (bytes)
total_rows        Int
text_column       String   (nama kolom CSV yang dipilih user sebagai sumber teks anotasi)
status            Enum     (active | archived)
annotation_order  Enum     (sequential | random) @default(sequential)
annotation_queue  String?  (JSON array of row_index, e.g. [42,7,103,...]; null jika sequential)
created_at        DateTime
updated_at        DateTime

// Computed
annotated_rows    Int      (count distinct row_index di tabel annotations)
```

### Annotation (Quadruple)
```
id                String   @id @default(cuid())
project_id        String   (FK → Project)
row_index         Int      (index baris 0-based dalam CSV — join ke data R2/IDB)

// Aspect
aspect_term       String   (teks aspect; diisi manual jika implicit)
aspect_implicit   Boolean  @default(false)
aspect_start      Int?     (char offset start dalam teks row; null jika implicit)
aspect_end        Int?     (char offset end dalam teks row; null jika implicit)

// Category
category_id       String   (FK → Category)

// Opinion
opinion_term      String   (teks opinion; diisi manual jika implicit)
opinion_implicit  Boolean  @default(false)
opinion_start     Int?     (char offset start dalam teks row; null jika implicit)
opinion_end       Int?     (char offset end dalam teks row; null jika implicit)

// Sentiment
sentiment         Enum     (positive | negative | neutral | mixed)

created_at        DateTime
updated_at        DateTime

@@unique([project_id, row_index, aspect_term, opinion_term])
```

Constraint UNIQUE mencegah duplikasi quadruple untuk kombinasi (project, row, aspect, opinion) yang sama. Endpoint POST menggunakan upsert (INSERT OR REPLACE) untuk menangani re-submission dengan aman.

### Category
```
id           String   @id @default(cuid())
project_id   String   (FK → Project)
name         String
usage_count  Int      @default(0)
created_at   DateTime
updated_at   DateTime

@@unique([project_id, name])
```

## Yang TIDAK Ada di D1

| Data | Lokasi penyimpanan |
|---|---|
| File CSV (mentah) | R2 (permanen, key: `projects/{id}/data.csv`) |
| Baris CSV (parsed) | IndexedDB browser (store `csv_rows`) |
| Index row saat ini | IndexedDB browser (store `progress`) |
| Status penyelesaian row | IndexedDB browser (store `row_statuses`) |
| Anotasi pending (belum disimpan) | Memory browser + IndexedDB (store `annotations`) |

| Migrasi | Deskripsi |
|---|---|
| `0000_initial` | Tabel `users`, `projects`, `categories` |
| `0001_annotations` | Tabel `annotations` (menggantikan `dataset_rows` + `quadruples`) |
| `0002_annotation_status` | Tambah kolom `status` ke `annotations` |

---

## Schema IndexedDB (Browser)

DB name: `acostator-{projectId}`

| Store | Key | Value |
|---|---|---|
| `csv_rows` | `row_index` | `{ row_index: number, text: string }` |
| `progress` | `"last"` | `{ last_row_index: number }` |
| `row_statuses` | `row_index` | `"pending" \| "completed" \| "skipped"` |
| `annotations` | `[row_index, localId]` | `IdbAnnotationRecord` |

---

## Category Recommendation Logic

Saat annotator memilih category untuk quadruple baru:

1. Ambil semua `Category` dalam project yang sama
2. Urutkan berdasarkan `usage_count DESC` (paling sering dipakai → paling atas)
3. Tampilkan sebagai suggestion list dengan fuzzy search
4. Jika tidak ada yang cocok → allow create new category

---

## Progress Calculation

```
project.annotated_rows = COUNT(DISTINCT row_index WHERE project_id = ?)
project.progress_pct   = (annotated_rows / total_rows) * 100
```

---

## Soft Delete Strategy

- Project: soft delete (tambah `deleted_at`)
- Annotation: hard delete boleh (bisa di-undo via re-annotate)
- Category: soft delete jika `usage_count = 0`, protected jika sedang dipakai
