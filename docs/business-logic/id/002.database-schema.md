# Acostator — Data Model

## Entity Overview

```
User
 └─ has many Projects
      └─ has many Annotations (quadruples)
           ├─ AspectTerm (span or implicit)
           ├─ OpinionTerm (span or implicit)
           ├─ Category (references CategoryPool)
           └─ Sentiment

Project
 └─ has many Categories (CategoryPool)

Catatan: DatasetRow TIDAK disimpan di D1. File CSV disimpan permanen di R2.
         Teks row di-load di browser saat anotasi.
```

---

## Entities

### User
```
id           String   @id (from OAuth provider)
github_id    String   @unique
username     String
email        String?
avatar_url   String?
created_at   DateTime
updated_at   DateTime
```

### Project
```
id                String   @id @default(cuid())
user_id           String   (FK → User)
name              String
description       String?
file_name         String   (nama file CSV asli)
file_key          String   (object key R2 untuk CSV yang diupload)
file_size         Int      (bytes)
total_rows        Int
text_column       String   (nama kolom CSV yang dipilih user untuk dianotasi)
status            Enum     (active | archived)
annotation_order  Enum     (sequential | random) @default(sequential)
annotation_queue  String?  (JSON array of row_index, e.g. [42,7,103,...]; null jika sequential)
created_at        DateTime
updated_at        DateTime

// Computed
annotated_rows    Int      (COUNT Annotation dengan row_index berbeda untuk project ini)
```

### DatasetRow

> **Tidak disimpan di D1.** File CSV disimpan permanen di R2. Data row (termasuk teks) di-fetch
> langsung dari R2 dan di-parse di browser saat anotasi menggunakan `text_column` milik project.
> D1 tidak menyimpan salinan konten row apapun.

### Annotation
```
id                String   @id @default(cuid())
project_id        String   (FK → Project)
row_index         Int      (index 0-based dari baris dalam CSV; merujuk posisi di CSV R2)

// Aspect
aspect_term       String   (teks aspect; diisi manual jika implicit)
aspect_implicit   Boolean  @default(false)
aspect_start      Int?     (char offset start; null jika implicit)
aspect_end        Int?     (char offset end; null jika implicit)

// Category
category_id       String   (FK → Category)

// Opinion
opinion_term      String   (teks opinion; diisi manual jika implicit)
opinion_implicit  Boolean  @default(false)
opinion_start     Int?     (char offset start; null jika implicit)
opinion_end       Int?     (char offset end; null jika implicit)

// Sentiment
sentiment         Enum     (positive | negative | neutral)

created_at        DateTime
updated_at        DateTime

@@index([project_id, row_index])
```

### Category
```
id           String   @id @default(cuid())
project_id   String   (FK → Project)
name         String   (e.g., "BATTERY", "DISPLAY", "SERVICE")
usage_count  Int      @default(0)  (untuk ranking rekomendasi)
created_at   DateTime

@@unique([project_id, name])
```

## CSV Import Format

File CSV yang di-upload harus memiliki minimal satu kolom teks. Saat upload, user memilih kolom yang ingin dianotasi melalui Column Picker. Nama kolom yang dipilih disimpan sebagai `text_column` di Project.

| Kolom | Keterangan |
|---|---|
| Kolom manapun yang dipilih user | Teks yang akan dianotasi |

Seluruh CSV disimpan apa adanya di R2. Tidak ada konten row yang diinsert ke D1.

---

## Category Recommendation Logic

Saat annotator memilih category untuk quadruple baru:

1. Ambil semua `Category` dalam project yang sama
2. Urutkan berdasarkan `usage_count DESC` (paling sering dipakai → paling atas)
3. Tampilkan sebagai suggestion list dengan fuzzy search
4. Jika tidak ada yang cocok → allow create new category

---

## Progress Calculation

```
project.annotated_rows = COUNT(DISTINCT row_index FROM Annotation WHERE project_id = ?)
project.progress_pct   = (annotated_rows / total_rows) * 100
```

Sebuah row dianggap sudah dianotasi jika minimal ada satu Annotation tersimpan untuknya. Tidak ada status row eksplisit di D1 — progress dihitung dari tabel Annotation.

---

## Soft Delete Strategy

- Project: soft delete (tambah `deleted_at`)
- DatasetRow: tidak disimpan di D1; tidak perlu strategi delete
- Annotation: hard delete boleh (bisa di-undo via re-annotate)
- Category: soft delete jika `usage_count = 0`, protected jika sedang dipakai
