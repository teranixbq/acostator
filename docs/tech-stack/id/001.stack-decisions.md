# Acostator — Keputusan Tech Stack

## Gambaran Umum

Dokumen ini mencatat setiap keputusan teknologi yang dibuat untuk Acostator, termasuk alasan dan alternatif yang dipertimbangkan. Update dokumen ini setiap kali ada dependency signifikan yang ditambahkan, diupgrade, atau diganti.

---

## Runtime: Cloudflare Workers

**Pilihan:** Cloudflare Workers (V8 isolate, bukan Node.js)

**Alasan:**
- Binding native ke D1 dan R2 — tidak ada network hop antara app dan storage
- Edge deployment — latensi rendah secara global
- Tidak ada server yang perlu dikelola
- Free tier yang cukup untuk research tool

**Alternatif yang dipertimbangkan:**
- Node.js di VPS — lebih familiar tapi perlu kelola server
- Next.js di Vercel — tidak ada D1/R2 native, butuh DB eksternal
- Bun di Fly.io — DX bagus tapi tetap butuh kelola server

---

## API Framework: Hono

**Pilihan:** Hono v4

**Alasan:**
- Dibangun khusus untuk edge runtime (Workers, Deno, Bun)
- Tidak ada ketergantungan Node.js — berjalan native di V8 isolate
- Typed routing dengan RPC mode — bisa berbagi types dengan frontend
- Ekosistem middleware (CORS, JWT, rate limiting)

**Alternatif yang dipertimbangkan:**
- Next.js API routes — butuh adapter `@cloudflare/next-on-pages`, menambah kompleksitas
- itty-router — lebih sederhana tapi fitur kurang, tidak ada typed middleware
- Express — hanya Node.js, tidak berjalan di Workers

---

## Frontend: React + Vite

**Pilihan:** React 19 + Vite 6

**Alasan:**
- Annotation tool sangat interaktif — model komponen React cocok
- SPA sudah cukup — tidak butuh SSR, semua data di-fetch setelah auth
- Vite cepat untuk iterasi development
- Ekosistem besar untuk UI primitives (shadcn/ui, Radix)

**Alternatif yang dipertimbangkan:**
- Solid.js — performa lebih baik tapi ekosistem lebih kecil
- Svelte — kurang familiar, lebih sedikit library UI komponen
- Vue — viable tapi preferensi tim untuk React

---

## Database: Cloudflare D1 (SQLite)

**Pilihan:** Cloudflare D1

**Alasan:**
- Binding native Workers — tidak ada connection pooling, tidak ada latensi
- SQLite relational — cocok untuk schema hierarkis (project→row→quadruple)
- Acostator read-heavy dengan write moderat — SQLite menangani ini dengan baik
- Free tier mencukupi untuk penggunaan skala penelitian

**Keterbatasan yang diakui:**
- D1 tidak cocok untuk workload write-heavy dengan concurrency tinggi
- SQLite tidak punya full-text search native (gunakan Drizzle `like` untuk fuzzy search category)
- Ukuran DB maks 10GB (cukup untuk metadata anotasi — file CSV aktual ke R2)

**Alternatif yang dipertimbangkan:**
- Cloudflare KV — tidak relational, buruk untuk query kompleks
- Neon (PostgreSQL) — lebih baik untuk write-heavy tapi menambah latensi network dari Workers
- PlanetScale — MySQL, menambah kompleksitas, ketergantungan eksternal

---

## File Storage: Cloudflare R2

**Pilihan:** Cloudflare R2

**Alasan:**
- Tidak ada egress fee — penting untuk download/export CSV besar
- Binding native Workers — akses langsung tanpa HTTP
- Ukuran objek maks 5GB (jauh di atas batas CSV 1GB kita)
- API kompatibel S3 jika suatu saat perlu migrasi

**Strategi upload:**
- File diupload langsung dari browser ke R2 via presigned URL
- Ini melewati batas request body Workers 100MB
- Worker membuat presigned URL dan menangani pemrosesan pasca-upload

**Alternatif yang dipertimbangkan:**
- Cloudflare KV — batas nilai 25MB, tidak cocok untuk file CSV
- AWS S3 — menambah ketergantungan eksternal dan biaya egress
- Local filesystem — tidak tersedia di Workers

---

## ORM: Drizzle ORM

**Pilihan:** Drizzle ORM

**Alasan:**
- Satu-satunya ORM mature dengan dukungan Cloudflare D1 first-class
- Query builder mirip SQL — tidak ada magic, query bisa diprediksi
- Schema definition TypeScript-first
- Ringan — tidak ada runtime overhead seperti Prisma

**Alternatif yang dipertimbangkan:**
- Prisma — tidak support D1 secara native (butuh workaround)
- Kysely — SQL builder yang bagus tapi tidak ada tooling migrasi
- Raw D1 queries — viable tapi kehilangan type safety dan manajemen migrasi

---

## Auth: GitHub OAuth (implementasi manual)

**Pilihan:** GitHub OAuth flow manual di Hono middleware

**Alasan:**
- NextAuth.js membutuhkan runtime Node.js — tidak berjalan di Workers
- Auth.js (v5) punya dukungan Workers eksperimental tapi belum production-ready
- GitHub OAuth flow mudah diimplementasi secara manual
- Session disimpan sebagai signed JWT di HTTP-only cookie

**Strategi session:**
- JWT ditandatangani dengan env variable `AUTH_SECRET`
- Cookie: `HttpOnly`, `Secure`, `SameSite=Lax`
- JWT payload: `{ userId, githubId, username }`
- Expiry: 30 hari, diperbarui saat aktivitas

**Alternatif yang dipertimbangkan:**
- Cloudflare Access — menambah ketergantungan infrastruktur, overkill untuk research tool
- Auth.js di Workers — eksperimental, belum production-ready
- Lucia Auth — viable tapi menambah dependency; manual lebih sederhana di sini

## Styling: Tailwind CSS v4

**Pilihan:** Tailwind CSS v4

**Alasan:**
- Utility-first — iterasi cepat pada UI anotasi
- v4 menggunakan CSS-first config (tidak perlu `tailwind.config.js`)
- Bekerja dengan Vite out of the box via `@tailwindcss/vite`

---

## UI Components: shadcn/ui

**Pilihan:** shadcn/ui (komponen copy-paste, bukan package)

**Alasan:**
- Komponen di-copy ke codebase — kontrol penuh, tidak ada black box
- Dibangun di atas Radix UI primitives — accessible by default
- Bekerja dengan Tailwind CSS
- Komponen utama yang dibutuhkan: Dialog, Popover, Command (untuk category selector), Badge, Button

---

## Testing: Vitest + `@cloudflare/vitest-pool-workers`

**Pilihan:** Vitest dengan Cloudflare Workers pool

**Alasan:**
- Test berjalan di dalam environment Workers miniflare yang sesungguhnya
- Binding D1 dan R2 tersedia di test — tidak perlu mocking untuk query DB
- Test runner yang sama (Vitest) untuk package frontend dan worker

**Yang perlu di-test:**
- Fungsi service layer (unit test)
- Route handler Hono (integration test dengan D1 nyata)
- Transisi state machine anotasi
- Edge case CSV parser

---

## Code Quality: Biome

**Pilihan:** Biome v1

**Alasan:**
- Satu tool menggantikan ESLint + Prettier
- 10-100x lebih cepat dari ESLint
- Zero config untuk proyek TypeScript + React
- Memastikan formatting konsisten di seluruh monorepo

**Config:** `biome.json` di root monorepo, berlaku untuk semua package.

---

## CI/CD: GitHub Actions

**Pipeline:**
```
push / PR → biome check → tsc --noEmit → vitest → deploy preview (PR only)
merge to main → deploy ke production
```

**Secrets yang dibutuhkan di GitHub:**
- `CLOUDFLARE_API_TOKEN` — untuk deploy Wrangler
- `CLOUDFLARE_ACCOUNT_ID`
- `GITHUB_CLIENT_ID` — GitHub OAuth app
- `GITHUB_CLIENT_SECRET`
- `AUTH_SECRET` — secret untuk signing JWT

---

## Monorepo: npm workspaces

**Pilihan:** npm workspaces (built-in di npm, tidak perlu tooling tambahan)

**Alasan:**
- Hanya tiga package (`web`, `worker`, `shared`) — Turborepo overkill
- Package shared types (`packages/shared`) menghindari duplikasi antara frontend dan worker
- Script dijalankan dari root: `npm run dev`, `npm run test`, `npm run lint`
