## Tech Stack

| Layer | Choice | Rationale |
|---|---|---|
| Runtime | Cloudflare Workers | Edge, serverless, native D1/R2 bindings |
| API Framework | Hono | Lightweight, built for Workers, zero Node.js dependency |
| Frontend | React + Vite (SPA) | Familiar ecosystem, no SSR needed for annotation tool |
| Language | TypeScript (strict) | Type safety for the complex data model |
| Database | Cloudflare D1 (SQLite) | Relational, fits project→row→quadruple structure |
| File Storage | Cloudflare R2 | CSV upload up to 1GB, no egress fees |
| ORM | Drizzle ORM | Only ORM with first-class D1 support |
| Auth | GitHub OAuth (manual) | NextAuth doesn't run on Workers |
| Styling | Tailwind CSS v4 | Utility-first, fast UI iteration |
| UI Components | shadcn/ui | Accessible, customizable |
| Testing | Vitest + `@cloudflare/vitest-pool-workers` | Native Workers environment in tests |
| Code Quality | Biome | Lint + format in one tool, fast |
| CI/CD | GitHub Actions | lint → typecheck → test → deploy preview |
| Deploy | Cloudflare Pages + Workers | Frontend on Pages, API on Workers |

## Key Modules (Deep Design)

### TextHighlighter
Smallest interface, largest implementation. Core of the tool.

```typescript
interface TextHighlighterProps {
  text: string
  highlights: Highlight[]
  activeHighlight: ActiveHighlight | null
  mode: 'aspect' | 'opinion' | 'idle'
  onSelect: (selection: TextSelection) => void
  onClear: (highlightId: string) => void
}
```

Responsibilities:
- Render text with highlight overlay
- Handle mouse selection for spans
- Display existing highlights (aspect = color A, opinion = color B)
- Prevent invalid overlapping highlights

### AnnotationWizard (State Machine)

```
idle → selecting_aspect → aspect_selected → selecting_opinion
     → opinion_selected → selecting_sentiment → selecting_category → idle
```

Invalid transitions are ignored, not thrown as errors.

### CategoryService
```typescript
interface CategoryService {
  getRecommendations(db: D1Database, projectId: string, query: string): Promise<Category[]>
  createCategory(db: D1Database, projectId: string, name: string): Promise<Category>
  incrementUsage(db: D1Database, categoryId: string): Promise<void>
}
```

Recommendations sorted by `usage_count DESC`, then fuzzy match against query.

## CSV Upload Flow

```
Client uploads file (max 1GB) directly to R2 via presigned URL
  → Worker validates: CSV format, column presence
  → Worker reads from R2, streaming parse with Papa Parse
  → Insert DatasetRows in batches (500 rows per D1 transaction)
  → Update Project.total_rows
  → Return project ID → redirect to project page
```

Direct-to-R2 upload avoids the Workers 100MB request body limit.

---

## Annotation Save Strategy

Each quadruple is saved immediately when the category step completes — no "submit" at the end. Prevents data loss if the browser is closed mid-annotation.

Row status changes to `completed` only when the user explicitly clicks "Mark as Complete".

---

## Export Flow

```
User clicks Export (JSON/CSV)
  → Worker queries all Quadruples for the project from D1
  → Join with DatasetRows
  → Transform to output format
  → Stream response as file download
```

## Auth Flow (GitHub OAuth — manual)

```
User clicks "Login with GitHub"
  → Redirect to GitHub OAuth (github.com/login/oauth/authorize)
  → GitHub redirects to /api/auth/callback?code=...
  → Worker exchanges code for access token
  → Worker fetches GitHub user profile
  → Worker creates/updates User in D1
  → Worker sets signed session cookie (JWT)
  → Redirect to /dashboard
```

All API routes validate the session cookie via auth middleware.

## CI/CD Pipeline (GitHub Actions)

```
push / PR
  └─ biome lint + format check
  └─ tsc --noEmit (typecheck)
  └─ vitest (unit tests with Workers pool)
  └─ deploy to Cloudflare Pages preview (on PR)
  └─ deploy to production (on merge to main)
```
