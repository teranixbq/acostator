### Key Design Decision: CSV stays in R2, D1 stores only quadruples

CSV rows are **never inserted into D1**. The browser fetches CSV from R2 once, caches it in IndexedDB, and all annotation work happens locally. Only the final quadruple data is synced to D1.

This decision was made after hitting the D1 "too many SQL variables" limit when trying to insert thousands of CSV rows in a single transaction.

## Tech Stack

| Layer | Choice | Rationale |
|---|---|---|
| Runtime | Cloudflare Workers | Edge, serverless, native D1/R2 bindings |
| API Framework | Hono | Lightweight, built for Workers, zero Node.js dependency |
| Frontend | React + Vite (SPA) | Familiar ecosystem, no SSR needed for annotation tool |
| Language | TypeScript (strict) | Type safety for the complex data model |
| Database | Cloudflare D1 (SQLite) | Relational, stores projects/categories/annotations only |
| File Storage | Cloudflare R2 | CSV upload up to 1GB, no egress fees, permanent storage |
| ORM | Drizzle ORM | Only ORM with first-class D1 support |
| Local Cache | IndexedDB (browser) | Stores parsed CSV rows, progress, row statuses, annotations |
| Auth | GitHub OAuth (manual) | NextAuth doesn't run on Workers |
| Styling | Tailwind CSS v4 | Utility-first, fast UI iteration |
| UI Components | shadcn/ui | Accessible, customizable |
| Testing | Vitest + `@cloudflare/vitest-pool-workers` | Native Workers environment in tests |
| Code Quality | Biome | Lint + format in one tool, fast |
| CI/CD | GitHub Actions | lint → typecheck → test → deploy |
| Deploy | Cloudflare Pages + Workers | Frontend on Pages, API on Workers |

## API Contract

```
GET    /health                              → { status: "ok" }
GET    /api/auth/github                     → redirect to GitHub OAuth
GET    /api/auth/callback                   → exchange code, set JWT cookie
POST   /api/auth/logout                     → clear cookie

GET    /api/projects                        → { data: Project[] }
POST   /api/projects                        → create project
GET    /api/projects/:id                    → { ...Project, text_column }
DELETE /api/projects/:id                    → delete project

POST   /api/projects/:id/upload/init        → { text_column } → { upload_url, key }
POST   /api/projects/:id/upload/complete    → finalize upload, store text_column
GET    /api/projects/:id/csv                → stream CSV (text/csv) from R2

GET    /api/projects/:id/annotations        → { data: Annotation[] }
POST   /api/projects/:id/annotations        → upsert quadruple (idempotent)
PUT    /api/projects/:id/annotations/:aId   → update annotation
DELETE /api/projects/:id/annotations/:aId  → delete annotation

GET    /api/projects/:id/categories         → { data: Category[] }
POST   /api/projects/:id/categories         → create category

GET    /api/projects/:id/export/json        → stream JSON
GET    /api/projects/:id/export/csv         → stream CSV
```

## CSV Upload Flow

```
1. User selects CSV file in browser
   → UploadCSVModal parses header row locally (no upload yet)
   → User picks which column contains the text to annotate (text_column)

2. POST /upload/init { text_column }
   → Worker returns presigned R2 upload URL + object key

3. Browser uploads file directly to R2 (avoids Workers 100MB body limit)

4. POST /upload/complete
   → Worker records text_column on project, updates total_rows
   → CSV stays in R2 permanently — never inserted into D1
```

## Annotation Flow (Browser-Local)

```
1. annotate.tsx loads:
   → GET /projects/:id  (to get text_column)
   → Check IndexedDB for cached CSV
      - If cached: load from IDB
      - If not: GET /projects/:id/csv → parse → save to IDB
   → GET /projects/:id/annotations → load existing quadruples into memory

2. User navigates rows (Previous / Next) — fully local, no API call
   → Progress saved to IDB on every navigation

3. User annotates a row:
   → TextHighlighter: click+drag to select aspect span
   → TextHighlighter: click+drag to select opinion span
   → Select category + sentiment
   → Click "Add Annotation" → saved to pendingAnnotations (memory) + IDB

4. User clicks "Complete":
   → POST /projects/:id/annotations for each pending quadruple (upsert)
   → Row status saved to IDB as "completed"
   → isDirty = false, syncStatus = "synced"
```

---

## Annotation Sync Strategy

Annotations are managed **locally first**:

- `pendingAnnotations` — in-memory list for current row
- IndexedDB (`annotations` store) — persisted across page refresh
- D1 — synced on "Complete" click via POST (upsert, idempotent)

The POST endpoint uses upsert (INSERT OR REPLACE) so re-submitting the same row is safe.

## TextHighlighter — Span Highlight System

Each annotation in the list gets a per-index color from `ANNOTATION_COLORS` palette (8 colors, rotating). The `TextHighlighter` component:

- Renders `existingQuadruples` highlights with per-index color (from `pendingAnnotations` mapped to `Quadruple[]`)
- Renders `aspectSpan` (active selection) as `active-aspect` style (blue + ring)
- Renders `opinionSpan` (active selection) as `active-opinion` style (emerald + ring)
- Uses `buildSegments()` to split text into colored character segments — last highlight wins on overlap

## Export Flow

```
User clicks Export (JSON/CSV)
  → Worker fetches CSV from R2 (text_column metadata on project)
  → Worker queries all annotations for the project from D1
  → Joins CSV rows + quadruples by row_index
  → Streams response as file download
```

## Auth Flow (GitHub OAuth — manual)

```
User clicks "Login with GitHub"
  → Redirect to GitHub OAuth (github.com/login/oauth/authorize)
  → GitHub redirects to /api/auth/callback?code=...
  → Worker exchanges code for access token
  → Worker fetches GitHub user profile
  → Worker creates/updates User in D1
  → Worker sets signed JWT in HttpOnly cookie (Domain=.apicode.my.id)
  → Redirect to FRONTEND_URL (Pages domain)
```

All API routes except `/api/auth/*` and `/health` validate the session cookie via auth middleware.

## CI/CD Pipeline (GitHub Actions)

```
push / PR to development
  └─ biome lint + format check
  └─ tsc --noEmit (typecheck)
  └─ vitest --passWithNoTests (unit tests with Workers pool)
```
