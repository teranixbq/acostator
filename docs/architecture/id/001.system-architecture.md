### Keputusan Arsitektur Kunci: CSV tetap di R2, D1 hanya simpan quadruples

Baris CSV **tidak pernah di-insert ke D1**. Browser fetch CSV dari R2 sekali, cache di IndexedDB, dan semua pekerjaan anotasi dilakukan secara lokal. Hanya data quadruple final yang di-sync ke D1.

Keputusan ini dibuat setelah menemukan batas "too many SQL variables" di D1 saat mencoba insert ribuan baris CSV dalam satu transaksi.

## Tech Stack

| Layer | Pilihan | Alasan |
|---|---|---|
| Runtime | Cloudflare Workers | Edge, serverless, binding native ke D1/R2 |
| API Framework | Hono | Ringan, dibuat untuk Workers, tanpa ketergantungan Node.js |
| Frontend | React + Vite (SPA) | Ekosistem familiar, tidak butuh SSR untuk annotation tool |
| Bahasa | TypeScript (strict) | Type safety untuk data model yang kompleks |
| Database | Cloudflare D1 (SQLite) | Relational, menyimpan projects/categories/annotations saja |
| File Storage | Cloudflare R2 | Upload CSV hingga 1GB, tanpa egress fee, penyimpanan permanen |
| ORM | Drizzle ORM | Satu-satunya ORM dengan dukungan D1 first-class |
| Cache Lokal | IndexedDB (browser) | Menyimpan baris CSV, progress, status row, anotasi |
| Auth | GitHub OAuth (manual) | NextAuth tidak bisa jalan di Workers |
| Styling | Tailwind CSS v4 | Utility-first, iterasi UI cepat |
| UI Components | shadcn/ui | Accessible, customizable |
| Testing | Vitest + `@cloudflare/vitest-pool-workers` | Environment Workers native di test |
| Code Quality | Biome | Lint + format dalam satu tool, cepat |
| CI/CD | GitHub Actions | lint → typecheck → test → deploy |
| Deploy | Cloudflare Pages + Workers | Frontend di Pages, API di Workers |

## API Contract

```
GET    /health                              → { status: "ok" }
GET    /api/auth/github                     → redirect ke GitHub OAuth
GET    /api/auth/callback                   → tukar code, set JWT cookie
POST   /api/auth/logout                     → hapus cookie

GET    /api/projects                        → { data: Project[] }
POST   /api/projects                        → buat project
GET    /api/projects/:id                    → { ...Project, text_column }
DELETE /api/projects/:id                    → hapus project

POST   /api/projects/:id/upload/init        → { text_column } → { upload_url, key }
POST   /api/projects/:id/upload/complete    → finalisasi upload, simpan text_column
GET    /api/projects/:id/csv                → stream CSV (text/csv) dari R2

GET    /api/projects/:id/annotations        → { data: Annotation[] }
POST   /api/projects/:id/annotations        → upsert quadruple (idempotent)
PUT    /api/projects/:id/annotations/:aId   → update anotasi
DELETE /api/projects/:id/annotations/:aId  → hapus anotasi

GET    /api/projects/:id/categories         → { data: Category[] }
POST   /api/projects/:id/categories         → buat category

GET    /api/projects/:id/export/json        → stream JSON
GET    /api/projects/:id/export/csv         → stream CSV
```

## Alur Upload CSV

```
1. User pilih file CSV di browser
   → UploadCSVModal parse header row secara lokal (belum upload)
   → User pilih kolom mana yang berisi teks untuk dianotasi (text_column)

2. POST /upload/init { text_column }
   → Worker kembalikan presigned R2 upload URL + object key

3. Browser upload file langsung ke R2 (menghindari batas body Workers 100MB)

4. POST /upload/complete
   → Worker catat text_column pada project, update total_rows
   → CSV tetap di R2 secara permanen — tidak pernah di-insert ke D1
```

## Alur Anotasi (Browser-Lokal)

```
1. annotate.tsx load:
   → GET /projects/:id  (untuk mendapat text_column)
   → Cek IndexedDB untuk CSV yang sudah di-cache
      - Jika ada: load dari IDB
      - Jika tidak: GET /projects/:id/csv → parse → simpan ke IDB
   → GET /projects/:id/annotations → load quadruple yang ada ke memory

2. User navigasi antar row (Previous / Next) — sepenuhnya lokal, tanpa API call
   → Progress disimpan ke IDB setiap navigasi

3. User anotasi sebuah row:
   → TextHighlighter: klik+drag untuk pilih span aspect
   → TextHighlighter: klik+drag untuk pilih span opinion
   → Pilih category + sentiment
   → Klik "Add Annotation" → disimpan ke pendingAnnotations (memory) + IDB

4. User klik "Complete":
   → POST /projects/:id/annotations untuk setiap quadruple pending (upsert)
   → Status row disimpan ke IDB sebagai "completed"
   → isDirty = false, syncStatus = "synced"
```

## Strategi Sync Anotasi

Anotasi dikelola **lokal terlebih dahulu**:

- `pendingAnnotations` — list in-memory untuk row saat ini
- IndexedDB (store `annotations`) — persisten meski halaman di-refresh
- D1 — di-sync saat klik "Complete" via POST (upsert, idempotent)

Endpoint POST menggunakan upsert (INSERT OR REPLACE) sehingga re-submit row yang sama aman dilakukan.

---

## TextHighlighter — Sistem Highlight Span

Setiap anotasi dalam list mendapat warna per-index dari palette `ANNOTATION_COLORS` (8 warna, berputar). Komponen `TextHighlighter`:

- Render highlight `existingQuadruples` dengan warna per-index (dari `pendingAnnotations` yang di-mapping ke `Quadruple[]`)
- Render `aspectSpan` (seleksi aktif) sebagai style `active-aspect` (biru + ring)
- Render `opinionSpan` (seleksi aktif) sebagai style `active-opinion` (emerald + ring)
- Menggunakan `buildSegments()` untuk membagi teks menjadi segmen karakter berwarna — highlight terakhir menang jika overlap

## Alur Export

```
User klik Export (JSON/CSV)
  → Worker fetch CSV dari R2 (metadata text_column ada di project)
  → Worker query semua anotasi untuk project dari D1
  → Gabung baris CSV + quadruples berdasarkan row_index
  → Stream response sebagai file download
```

## Alur Auth (GitHub OAuth — manual)

```
User klik "Login with GitHub"
  → Redirect ke GitHub OAuth (github.com/login/oauth/authorize)
  → GitHub redirect ke /api/auth/callback?code=...
  → Worker tukar code dengan access token
  → Worker fetch profil user GitHub
  → Worker buat/update User di D1
  → Worker set signed JWT di HttpOnly cookie (Domain=.apicode.my.id)
  → Redirect ke FRONTEND_URL (domain Pages)
```

Semua route API kecuali `/api/auth/*` dan `/health` memvalidasi session cookie via auth middleware.

## CI/CD Pipeline (GitHub Actions)

```
push / PR ke development
  └─ biome lint + format check
  └─ tsc --noEmit (typecheck)
  └─ vitest --passWithNoTests (unit tests dengan Workers pool)
  └─ deploy ke Cloudflare Workers (otomatis saat push ke development)
```

Base branch untuk semua pekerjaan adalah `development`. `main` hanya untuk production.
