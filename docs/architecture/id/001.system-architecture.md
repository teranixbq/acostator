## Tech Stack

| Layer | Pilihan | Alasan |
|---|---|---|
| Runtime | Cloudflare Workers | Edge, serverless, binding native ke D1/R2 |
| API Framework | Hono | Ringan, dibuat untuk Workers, tanpa ketergantungan Node.js |
| Frontend | React + Vite (SPA) | Ekosistem familiar, tidak butuh SSR untuk annotation tool |
| Bahasa | TypeScript (strict) | Type safety untuk data model yang kompleks |
| Database | Cloudflare D1 (SQLite) | Relational, cocok untuk struktur project→row→quadruple |
| File Storage | Cloudflare R2 | Upload CSV hingga 1GB, tanpa egress fee |
| ORM | Drizzle ORM | Satu-satunya ORM dengan dukungan D1 first-class |
| Auth | GitHub OAuth (manual) | NextAuth tidak bisa jalan di Workers |
| Styling | Tailwind CSS v4 | Utility-first, iterasi UI cepat |
| UI Components | shadcn/ui | Accessible, customizable |
| Testing | Vitest + `@cloudflare/vitest-pool-workers` | Environment Workers native di test |
| Code Quality | Biome | Lint + format dalam satu tool, cepat |
| CI/CD | GitHub Actions | lint → typecheck → test → deploy preview |
| Deploy | Cloudflare Pages + Workers | Frontend di Pages, API di Workers |

## Modul Utama (Deep Design)

### TextHighlighter
Interface terkecil, implementasi terbesar. Inti dari tool ini.

```typescript
interface TextHighlighterProps {
  text: string
  highlights: Highlight[]
  activeHighlight: ActiveHighlight | null
  mode: 'aspect' | 'opinion' | 'idle'
  onSelect: (selection: TextSelection) => void
  onClear: (highlightId: string) => void
}
```

### AnnotationWizard (State Machine)

```
idle → selecting_aspect → aspect_selected → selecting_opinion
     → opinion_selected → selecting_sentiment → selecting_category → idle
```

Transisi yang tidak valid di-ignore, bukan di-throw sebagai error.

## Alur Upload CSV

```
Client upload file (maks 1GB) langsung ke R2 via presigned URL
  → Worker validasi: format CSV, minimal ada satu kolom
  → Worker simpan metadata file ke D1 (Project.file_key, Project.total_rows)
  → Worker kembalikan daftar kolom ke browser
  → User pilih kolom yang berisi teks untuk dianotasi (Column Picker)
  → Worker simpan kolom yang dipilih sebagai Project.text_column
  → Redirect ke halaman project
```

Tidak ada row yang diinsert ke D1 saat upload. CSV tetap di R2 secara permanen.
Upload langsung ke R2 menghindari batas request body Workers 100MB.

---

## Alur Load Anotasi

```
User buka halaman anotasi untuk sebuah project
  → Browser fetch CSV dari R2 via signed URL (diterbitkan Worker)
  → Browser parse CSV di sisi client dengan Papa Parse
  → Row dibaca dari kolom yang sesuai dengan Project.text_column
  → UI anotasi render teks row langsung dari CSV yang sudah di-parse
```

D1 tidak diquery untuk teks row — semua konten row berasal dari R2 saat runtime.

---

## Strategi Simpan Anotasi

Setiap quadruple (Annotation) langsung disimpan ke D1 saat step sentiment selesai — tanpa "submit" di akhir. Mencegah kehilangan data jika browser ditutup di tengah anotasi.

Progress dihitung dari jumlah `row_index` berbeda di tabel Annotation — tidak ada field status row terpisah di D1.

## Alur Export

```
User klik Export (JSON/CSV)
  → Worker fetch CSV asli dari R2
  → Worker query semua Annotation untuk project dari D1
  → Worker join baris CSV dengan Annotation berdasarkan row_index
  → Transform ke format output (JSON atau CSV)
  → Stream response sebagai file download
```

---

## Alur Auth (GitHub OAuth — manual)

```
User klik "Login with GitHub"
  → Redirect ke GitHub OAuth
  → GitHub redirect ke /api/auth/callback?code=...
  → Worker tukar code dengan access token
  → Worker fetch profil user GitHub
  → Worker buat/update User di D1
  → Worker set signed session cookie (JWT)
  → Redirect ke /dashboard
```

## CI/CD Pipeline (GitHub Actions)

```
push / PR
  └─ biome lint + format check
  └─ tsc --noEmit (typecheck)
  └─ vitest (unit test dengan Workers pool)
  └─ deploy ke Cloudflare Pages preview (saat PR)
  └─ deploy ke production (saat merge ke main)
```
